# Phase 2 — Close the Cost Loop: MS Text-First, Output Caps, Stage Attribution

## Context correction (important)

The Tier-0 text-first gate for **question papers** already exists and is ON by default
(`commands.rs:1454`, `MERGEMARK_TEXT_FIRST=0` disables): `try_text_first_extraction`,
`try_text_first_batch_extraction`, crop-first, slim prompts/schemas, zero-image tests.
Earlier cost rankings claiming "spans still ship images" were wrong.

**Verified remaining levers** (this phase's scope — user chose "Full Phase 2"):

1. **Mark-scheme pipeline has zero text-first** — `run_markscheme_pipeline`
   (pipeline.rs:6171) + `read_markscheme_window` (~6040–6169) send every 3-page
   window as `ImageDetail::High` full-page images with the FULL extraction schema and
   repairs. MS is ~40% of a QP+MS import's pages → likely the largest remaining
   vision spend on born-digital papers.
2. **`max_output_tokens: 32768` on every call** — text-first calls emitting ~300
   completion tokens reserve the same ceiling as 4-page vision extractions.
3. **No stage-level cost data** — `TokenTotals` is two global atomics;
   `import_cost_logs` (db.rs:266) stores run totals only. We cannot answer
   "where does money go" from data.
4. **Gate ignores `seg_confidence`** — `extract_span` counts ANY detected figure as
   supply (`fig_count == 0` check, pipeline.rs:3374–3376); a 0.2-confidence detection
   satisfies it and silently starves the vision fallback.

## Work items

### A. Mark-scheme text-first (biggest win)

Port the question-pipeline pattern to MS windows:

- **Gate** (`window_text_reliable(pages[start..end]) -> bool`), conservative:
  - every page in the window has non-empty `page.text`
  - combined text ≥ 400 chars
  - replacement-char (`\u{FFFD}`) rate < 2%
  - no `[DIAGRAM` / `Figure N shows` markers in the window text (worked figures
    need vision boxing — `saved_diagrams` dedupe exists for a reason)
- **Call**: `&[] as &[String]` images + new `markscheme_text_first_system_prompt()`
  (slim: no diagram-boxing rules) + new `markscheme_text_first_json_schema()`
  (drop diagram-bbox fields; `AiAnswer` fields already serde-default tolerant).
- **Safety fallback**: if the text-first response contains placeholder-like markers
  or parse fails → re-ask the SAME window with the existing vision path (current
  code, unchanged). Bounded by existing `max_attempts`.
- **Counter**: `ImportReport.ms_text_first: usize` (+ absorb + PATH_SUMMARY line).
- Keep `ImageDetail::High` vision windows exactly as-is for non-qualifying windows.

### B. Per-stage output caps

- Add `fn stage_output_cap(stage: StageTag) -> u32` and pass
  `min(config.max_output_tokens, cap)` at each call site:
  | Stage | Cap |
  |---|---|
  | TextFirstExtraction / BatchTextFirst | 2048 |
  | MsTextFirst | 3072 |
  | CropFirst | 2048 |
  | VisionSpan / FallbackPage | 8192 |
  | MsWindow (vision) | 8192 |
  | StructurePass / DiagramAudit | 2048 |
- Rationale: outputs are billed at the 8× rate; schema-mode responses never
  legitimately approach 32k for single questions. Truncation guard
  (`response_was_truncated`) already converts ceilings into repair rounds safely.

### C. Stage-level token attribution

- `enum StageTag` (as in table above) in pipeline.rs.
- `chat_with_permit` gains a `stage: StageTag` parameter (~15 mechanical call-site
  edits); `TokenTotals` gains `stages: Mutex<BTreeMap<StageTag, (u64,u64)>>` +
  `snapshot_stages()`.
- `ImportReport.stage_breakdown: Vec<StageCost { stage, prompt, completion }>`
  (camelCase serde, like existing fields).
- **Persistence**: `import_cost_logs` gains `stage_breakdown TEXT` column.
  `init_db` migration guard: run `ALTER TABLE import_cost_logs ADD COLUMN
  stage_breakdown TEXT`, ignore the duplicate-column error (matches the
  CREATE-TABLE-IF-NOT-EXISTS style already used). `log_import_cost` gains the
  param; `ImportCostRecord` + SELECT gain the field; commands.rs serializes
  `report.stage_breakdown` into it.
- Frontend display is OUT of scope (data lands in DB; UI reads it later).

### D. Gate hardening with `seg_confidence`

- In `extract_span` (and the same-page batch path): figure SUPPLY counting uses
  only candidates with `seg_confidence >= 0.5`; below-threshold detections still
  attach when explicitly referenced, but never satisfy `fig_count` on their own.
- Effect: weak detections no longer silently starve the vision fallback —
  text-first proceeds only when figure supply is genuinely trustworthy.

## Tests (MockLlm patterns already in place)

1. MS text-first: text-rich window → zero images in body, slim schema referenced,
   answers parsed; counter incremented.
2. MS fallback: text-first response containing a diagram marker → second call
   carries images (vision path), answers still produced.
3. Unreliable window (empty text page / CID garbage) → straight to vision, one call.
4. Stage attribution: two calls tagged different stages → `snapshot_stages()`
   correct; `stage_breakdown` lands in `ImportReport`.
5. Output caps: captured request body `max_tokens == min(32768, cap)` per stage.
6. seg_confidence gate: single 0.3-confidence figure + figure-referencing text →
   vision path taken; same figure at 0.8 → text-first taken.
7. DB: `log_import_cost` round-trips `stage_breakdown` (existing db test harness).

## Out of scope (explicit)

- Zero-call deterministic spans (Rust-only transcription) — needs its own quality
  harness; next phase, flag-gated.
- Frontend UI for stage breakdown.
- Prompt-prefix byte-stability audit (implicit caching) — separate micro-phase.

## Order of work

1. StageTag + TokenTotals stages + chat_with_permit param (mechanical, compiles green)
2. Output caps table + call-site mins
3. seg_confidence gate hardening + tests
4. MS text-first (prompt, schema, gate, fallback, counter) + tests
5. DB column migration + persistence + test
6. Full `cargo test`; manual QP+MS physics import; diff `import_cost_logs` rows
   before/after — expect MS window rows to show near-zero image-driven prompt
   tokens on born-digital mark schemes.

## Risks

- MS answers are terse and MS validation is weaker than QP (no marks checksums) —
  mitigated by the conservative gate, placeholder fallback, and unchanged
  quarantine path. Recommend one manual spot-check of a text-first MS import in
  the UI before trusting it broadly.
- ALTER TABLE migration must be idempotent (duplicate-column error swallowed).
