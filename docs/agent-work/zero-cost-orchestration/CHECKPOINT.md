**Architecture (born-digital question papers).** `src-tauri/src/layout.rs` is a geometry-first layout engine over PDFium glyph boxes/baselines, font identities, rules and vector paths. It builds reading-order lines and maths (fractions, radicals including a bare sign over a bracketed radicand, scripts, big operators with limits and the line they are set in, `\lim_{…}`, matrices, cases with the condition column aligned across rows, accents, vector arrows), tables, code, page furniture and an exact line-level question map (heading column, END/section breaks, running furniture, lead-in and reference runs, mid-paper blank pages). `pipeline::run_question_pipeline` uses this map and text when layout evidence covers every page; `deterministic::layout_transcription` replaces the text carver for those spans; the text-layer carver is a fallback only. `layout::layout_document` lays out a whole document so cross-page furniture is known first.

**Figures.** Layout regions (oblique paths, images placed through nested form matrices, axis growth, nearby drawings) ∪ detector figures, chosen per question with y-anchored placeholders; exact crops (`geometry::crop_exact`, zero padding for inline formula pictures; an inkless crop is rejected as `CropReject::Blank`); figure labels are gathered outward to a fixpoint (axis titles beyond tick values), never from a nearer figure; option letters bind labelled drawings, whose card puts the marks tag before the options. Pictures repeated at one place across pages (QR codes, logos, margin strips, page backgrounds) are page furniture; only small ones (≤ 90 pt) are painted out of a crop they touch.
